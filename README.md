# Straty Kuchnia

Учёт кухонных страт: **программа на компьютере менеджера** с локальной базой,
настройками и отчётностью — и **форма на телефоне повара**, где нет ничего,
кроме ввода страты.

Устроено как Beer Count, только сильно проще: ни беччек, ни рецептур, ни
денег. **Позиция = название + единица, и всё.** Программа сама складывает
списания по позициям за месяц — это и есть цифра, которую переписывают в
свою систему.

Интерфейс — польский. База — SQLite рядом с программой.

---

## Как это устроено

```
   телефон повара                 дроплет                 компьютер менеджера
┌──────────────────┐      ┌────────────────────┐      ┌──────────────────────┐
│ /form?t=ТОКЕН    │      │  очередь згłoszeń  │      │  StratyKuchnia.exe   │
│ pozycja + ilość  │ ───► │  (почтовый ящик,   │ ───► │  Zgłoszenia →        │
│ powód + imię     │ POST │   30 дней, и всё)  │ GET  │  Zatwierdź →         │
│ „Wyślij”         │      │                    │ ◄─── │  kuchnia.db (правда) │
└──────────────────┘      └────────────────────┘ DEL  └──────────────────────┘
```

**Правда живёт только на компьютере менеджера.** Сервер ничего не считает и
не хранит историю: он держит зашлушения, пока их не заберут. Потерять
арендованную машину не страшно — данные не там.

| Кто | Что делает |
|---|---|
| Повар | Сканирует QR, набирает позиции в зашлушение, жмёт `Wyślij`. Без сети — запись ложится в очередь на телефоне и уедет сама. |
| Менеджер | `Zgłoszenia` → проверяет, при нужде правит, `Zatwierdź`. Плюс ручной ввод, правка журнала, отчёты, каталог. |
| Владелец | `/admin` на сервере: кухни, токены, QR-коды. |

С версии 1.1 по той же схеме ходят **чек-листы** (уборка, температуры,
журналы охлаждения): менеджер собирает их в конструкторе, повара и
супервайзеры заполняют с телефона или планшета, заполненные копии ложатся в
архив на компьютере менеджера. Подробно — раздел «Чек-листы» ниже.

## Быстрый старт (разработка)

```powershell
pip install -r requirements.txt
python main_kuchnia.py
```

При первом запуске программа создаёт `kuchnia.db` рядом с собой и заливает
стартовый каталог. Дальше — `Ustawienia`.

Сервер локально, для проверки формы:

```powershell
python server\kitchen_server.py
```

(нужен `KUCHNIA_ADMIN_PASSWORD` в окружении; форма — `http://127.0.0.1:8788/form?t=ТОКЕН`)

### Сборка .exe

```powershell
pyinstaller StratyKuchnia.spec
```

> ⚠ **`--noconfirm` стирает папку `dist` целиком.** Собранная программа держит
> базу рядом с собой (`dist\StratyKuchnia\kuchnia.db`), поэтому пересборка
> сносит всё, что было натыкано при проверке. Если данные нужны — сначала
> скопируй базу в сторону. У клиента такой беды нет: установщик кладёт
> программу в `C:\StratyKuchnia` и исключает `kuchnia.db` из перезаписи.

Потом `setup.iss` в Inno Setup Compiler → `Output\StratyKuchnia-Setup-X.Y.Z.exe`.

### Выпуск обновления (как в Beer Count)

Вручную собирать ничего не нужно — это делает GitHub:

1. Поднять `APP_VERSION` в `main_kuchnia.py` (например, `1.2.0`), закоммитить
   и запушить в `main`. Сам по себе push в `main` ничего не выпускает.
2. Поставить тег с той же версией и запушить его:
   ```powershell
   git tag v1.2.0
   ```
   ```powershell
   git push origin v1.2.0
   ```
3. GitHub Actions (`release.yml`) гоняет все проверки, собирает exe и
   установщик и публикует Release `Straty Kuchnia 1.2.0` с
   `StratyKuchnia-Setup-1.2.0.exe` и `SHA256SUMS.txt`. Красный тест или
   тег, не совпадающий с `APP_VERSION`, — релиза нет.
4. У менеджера при следующем запуске программы в боковой панели
   появляется «Aktualizacja 1.2.0». Клик → установщик скачивается,
   сверяется по SHA256 и ставится тихо; программа закрывается и через
   несколько секунд запускается сама. `kuchnia.db` установщик не трогает.
   Проверить вручную — `Ustawienia → O programie → Sprawdź aktualizacje`.

Тег с дефисом (`v1.2.0-rc.1`) даёт пробный релиз: программа его не видит.
`Run workflow` на вкладке Actions — пробная сборка без релиза, установщик
лежит в Artifacts.

> Версия **1.0.0 обновляться не умеет** — проверка появилась в 1.1.0.
> На компьютер менеджера первый раз установщик ставится руками,
> дальше — сам.

> Сервер (форма и чек-листы на дроплете) так не обновляется — его
> выкладка по-прежнему по `DEPLOY.md`.

## Разделы программы

**Podsumowanie** — главный экран. Месяц, четыре счётчика и таблица «позиция →
сколько ушло». Вкладки: `Pozycje`, `Wg miesięcy` (матрица позиция × месяц),
`Powody`, `Kategorie`. Кнопки Excel — за месяц и за весь период.

**Straty** — журнал: фильтры (месяц/весь период, категория, причина, человек,
поиск), ручной ввод, правка и удаление. Иконка у строки показывает, пришла
она с телефона или вбита руками.

**Zgłoszenia** — очередь с сервера. Каждая карточка: кто, когда, какие
позиции. `Zatwierdź` — принять целиком, `Popraw i zatwierdź` — поправить
строки, `Odrzuć` — выбросить. Ниже — последние принятые с кнопкой `Cofnij`.

**Checklisty** — `Archiwum` (заполненные копии: фильтры, сортировка, превью,
печать, резервные копии) и `Szablony` (список шаблонов и конструктор).

**Ustawienia** — `Pozycje` (каталог), `Powody`, `Serwer` (адрес, токен,
«Sprawdź połączenie», «Wyślij katalog na serwer»), `O programie` (версия,
путь к базе, кнопка резервной копии).

## Модель данных

```
items    позиция: название, категория, единица (szt | kg | g | l | ml)
reasons  причины списания
losses   страта: дата, позиция, количество, единица, qty_base, причина,
         кто, заметка, источник (qr/ręcznie), report_id
losses_confirmed  какие зашлушения уже приняты
config   имя кухни, адрес сервера, токен, тема
```

Единицы живут в трёх измерениях с базой `szt` / `g` / `ml`. Введённое
количество хранится как есть (`qty`, `unit`) **и** в базовой единице
(`qty_base`). Суммируем всегда по `qty_base`, показываем в единице позиции —
поэтому «300 g» и «1 kg» складываются в «1.3 kg», а «1 kg» и «1 l» сложить
нельзя по построению: единица из чужого измерения отклоняется на входе.

## Чек-листы

```
 конструктор (ПК менеджера) ──► сервер ──► телефон / планшет (заполнение)
        архив копий         ◄── сервер ◄──        «Wyślij»
```

**Шаблон** — это секции-таблицы. У секции есть колонки (у каждой свой тип
ячейки) и строки. Этого хватает и на «галочку напротив пункта», и на
температурный лист «станция × время», и на журнал.

| Что настраивается | Где |
|---|---|
| Название, описание, периодичность | карточка «Podstawowe» |
| Дополнительные поля над и под таблицами (смена, подпись супервайзера…) | «Dodatkowe pola nad tabelami», «Pola pod tabelami» |
| Колонки секции: название, тип, обязательность, допуск min/max, единица, варианты списка | «KOLUMNY» |
| Строки: текст пункта, свой допуск min/max, выключенные ячейки | «WIERSZE» |
| Режим строк: постоянный список или журнал (строки дописывает заполняющий) | «WIERSZE» |
| Подпись под секцией | галочка у заголовка секции |

Типы ячеек: галочка, Tak / Nie / N/D, текст, число, температура, время,
дата, список, подпись. Секции, колонки и строки двигаются стрелками и
дублируются; «Wklej listę…» превращает вставленный текст в строки — по
одной на линию. Шаблон можно сохранить в файл `.json` и загрузить на
другой кухне.

**Как это ведёт себя при заполнении**

- **Дата.** Пустое поле — кнопка «Dotknij — dziś»: одно касание ставит
  сегодняшнюю дату (дату смены: до 5:00 — вчерашнюю, как у страт). После
  этого её можно поменять системным календарём. Время в ячейках работает
  так же: касание ставит текущее.
- **Подпись** — касание подставляет имя из поля «Kto wypełnia».
- **Допуски.** Значение вне min/max подсвечивается красным сразу при вводе
  и попадает в счётчик «odchylenia». Допуск строки важнее допуска колонки:
  у морозилки и у горячей витрины одна колонка, а нормы разные.
- **Черновик** сохраняется на устройстве при каждом касании. Температурный
  лист заполняют весь день — закрытая вкладка его не сотрёт. Черновик живёт
  в браузере конкретного устройства: начатое на одном планшете на другом
  не видно.
- **Без сети** отправленный лист ложится в очередь и уезжает сам.
- На планшете секция рисуется таблицей, как на бумаге; на телефоне каждая
  строка раскладывается карточкой.

**Решения**

- **Копия несёт снимок шаблона.** Правка или удаление шаблона старые копии
  не меняет: в архиве лист всегда такой, каким его заполняли.
- **Шаблоны уезжают на сервер сами** — после сохранения в конструкторе и
  после любой правки в списке (скрыть, удалить, переставить). В отличие от
  каталога позиций, отдельной кнопки ждать не нужно; она есть на случай,
  если сервер был недоступен.
- **Копии не требуют подтверждения.** Страту менеджер проверяет, а
  чек-лист — это запись о том, что было сделано; он сразу ложится в архив.
  Новые копии помечены точкой и считаются в меню.
- **Сервер хранит заполненный лист до 30 дней** и удаляет его, как только
  приложение забрало копию. Приложение проверяет сервер при запуске, по
  кнопке «Odśwież» и само каждые 5 минут.
- **Печать — через браузер.** «Drukuj / PDF» открывает самодостаточную
  HTML-страницу; оттуда печать или «Zapisz jako PDF». Отдельного
  PDF-движка в программе нет.
- **Резервные копии** (`Archiwum → Kopie zapasowe`): ZIP с шаблонами и всеми
  копиями (внутри обычный JSON). Восстановление только добавляет
  недостающее. Можно указать папку (например, в OneDrive) — программа сама
  кладёт туда копию раз в день, если что-то изменилось, и держит последние
  30 файлов. Кроме того, чек-листы лежат в том же `kuchnia.db`, так что
  общая «Kopia zapasowa bazy» их тоже захватывает.

Стартовые шаблоны (`Szablony → Wgraj szablony startowe`) перенесены с
бумажных листов: Daily Cleaning Checklist, Weekly Cleaning Schedule,
Temperature Checklist, Cooling / Re-Heating Temperature Log. Что в них —
толкование, а не текст с листа, перечислено в шапке `checklist_presets.py`.

## Решения, которые стоит помнить

- **Дата страты — дата смены.** До 5:00 утра списание относится к
  предыдущему дню: повар в 01:30 закрывает вчерашнюю смену. Так же в Beer Count.
- **Подтверждение идемпотентно.** Перед записью удаляются строки с тем же
  `report_id`, поэтому повторное нажатие или обрыв связи не удваивают страты.
  `Cofnij` в истории убирает всё зашлушение целиком.
- **Позиция ищется сначала по id, потом по имени.** Каталог на сервере может
  отстать от локального; имя переживает и переустановку программы. Что не
  нашлось — не выбрасывается, а подсвечивается: менеджер выберет руками.
- **Сервер не считает единицы.** `qty` едет строкой («0,5» с польской
  клавиатуры доезжает как есть), вся математика — в приложении.
- **Единицу позиции с историей менять можно только внутри измерения**
  (`kg ↔ g`, `l ↔ ml`). `kg → szt` превратило бы 3.4 kg в 3.4 штуки.
- **Позицию с историей не удалить случайно**: программа предлагает скрыть её
  (`active=0`) — из формы исчезнет, прошлые месяцы останутся целыми.
- **Имена сравниваются по-польски.** SQLite `COLLATE NOCASE` знает только
  ASCII, поэтому «Łosoś» и «łosoś» проехали бы как разные позиции — проверка
  дублей сделана в Python.
- **Сортировка «wg ilości» не смешивает единицы.** 7 l и 3 kg сравнивать
  бессмысленно, поэтому позиции сортируются внутри групп единиц.
- **Денег нет.** Сознательно: чтобы суммы в злотых не врали, кто-то должен
  вести прайс-лист. Понадобится — в `items` добавляется `unit_cost`,
  остальное считается поверх `qty_base`.
- **База — один файл.** `Ustawienia → O programie → Kopia zapasowa bazy`
  делает корректный снимок (`sqlite backup`, а не копирование файла).

## Если программа не запускается

При падении на старте окно показывает текст ошибки, а полный трейсбек ложится
в **`kuchnia-error.log` рядом с программой** — у windowed-сборки нет консоли,
и без этого файла падение выглядит как «просто не запустилось».

| Что видно | Что это |
|---|---|
| Окно висит на бесконечной загрузке | Осиротевшее окно Flet: процесс Python убит, а окно осталось. Закрыть его и запустить заново. В диспетчере это процессы `flet` без родителя. |
| Окно с красной ошибкой | Прислать текст или `kuchnia-error.log` — там причина целиком |
| «Windows защитила ваш ПК» | Установщик не подписан. `Подробнее → Выполнить в любом случае` — как у Beer Count |
| Окна нет вообще | Проверить `kuchnia-error.log`; если файла нет — программа даже не стартовала (антивирус, права на папку) |

Проверить занятость: программа держит базу в своей папке, вторую копию
запускать не нужно — SQLite в режиме WAL это переживёт, но два окна будут
показывать одни и те же данные.
